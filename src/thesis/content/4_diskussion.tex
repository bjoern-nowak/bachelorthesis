\chapter{Diskussion}\label{ch:diskussion}

\begin{enumerateWithCode}{D}
    \item Ein Export-Endpunkt, welches ein Charakter in einem Format zurück gibt, das kompatibel zu anderen Softwares ist, ist im allgemeinen Benutzenden-freundlich.
    Noch besser wäre ein Import-Endpunkt gewesen, welches fremde Formate in das Eigene konvertiert.
    Dies würde eine Migration von einer anderen Software erleichtern und damit die Zahl der Benutzenden und möglichen Mitwirkenden potenziell vergrößern.

%    \item Regel(-Funktionen) könnten zwar expliziert definiert sein (z.B. 'profession\_requires\_culture("<profession>","<culture>").' ) anstatt generisch (z.B. 'requires(profession("<profession>"),culture("<culture>")).' ) macht das Konzept aber zu starr, wodurch bei der Wartung und Erweiterung mehr Arbeit in Python bei der reimplementierung der gleichen Regel in einer anderen Ausprägung machen würde.
%    Limitert ist die generik jedoch weiterhin durch die fest implementieren Character-Merkmale

    \item Durch die generierten Validierungsfehler und -warnungen, weiß der Benutzende zwar was nicht richtig ist, es fehlt aber der helfende Hinweis, wie es richtig wäre.
    Die Parameter der Rückmeldungen sollten daher um solche Informationen ergänzt werden.
    Auch denkbar ist es ein Endpunkt bereitzustellen, welcher mögliche Merkmalsausprägungen, unter Beachtung der zu verwenden Regelbücher und vor allem der bereits gewählten Merkmale, identifiziert und zurückgibt.
    Dies kann \ggf unter Angabe des gesuchten Merkmals passieren oder hierarchisch, gemäß der Schritte aus \Zitat{RWiki-Erstellung}, für fehlende Merkmale passieren.
    \ZB wenn für einen Charakter bereits eine Spezies und Kultur gewählt wurde, so könnte dieser Endpunkt mögliche Professionen bennen.
    Dazu muss das Schema des Charakters angepasst werden, so das diese Merkmale keine Pflichtfelder mehr sind (außer bei Listen, da diese leer sein können).

    \item Des Weiteren werden die Charakter-Validierungswarnungen immer ausgeben.
    Es fehlt die Möglichkeit diese zu ignorieren \bzw als \textquote{von der Spielleitung akzeptierte Abweichungen} zu markieren.
    Dazu kann die \Abk{API} angepasst werden, sodass der Validierungsendpunkt zusätzlich eine Liste der konkret zu ignorierenden Warnungen (so wie sie zuvor zurückgeben wurden) annimmt.

    \item Viele Regeln werden im \Abk{LP} für ähnliche Merkmale wiederholt.
    Zur Vermeidung dessen könnte man diese Merkmale auf eine gemeinsames \Tech{Clingo}-\Begriff{Funktion} (\Begriff{Gruppe}) abbilden.
    Wodurch die Regel nur noch einmalig für diese \textquote{Gruppe} definiert werden muss.
    Die Gruppe kann von den bestehenden Charakter-Fakten abgeleitet werden oder diese ersetzen, letzteres ist jedoch nicht zu empfehlen, da Ersteres mehr Freiheiten bietet.
    Das \Listing[KP]{lst:modellierung-von-strukturell-ahnlichen-merkmalen-in-einer-gruppe} zeigt dies beispielhaft.
    Dadurch müsste jedoch die Interpretation der Ergebnis-Fakten angepasst werden, weil das erste Argument nicht mehr (ausschließlich) eine \Tech{Clingo}-\Begriff{Funktion} als Merkmal ist, sondern dessen Argumente direkte Argumente des Ergebnis-Fakts wären (vgl. \Anhang[KP]{sec:hero-validation-interpreter.py}).

    \begin{listing}[htbp]
        \caption{Modellierung von strukturell ähnlichen Merkmalen in einer Gruppe}\label{lst:modellierung-von-strukturell-ahnlichen-merkmalen-in-einer-gruppe}
        \begin{minted}{clingo}
%% Beispiel einer Regel-Wiederholung
missing_min_lvl(talent(T,LVL),MIN) :- talent(T,LVL), MIN = 0, LVL < MIN.
missing_min_lvl(combat_technique(CT,LVL),MIN) :- combat_technique(CT,LVL), MIN = 0, LVL < MIN.
%% Option A: zusätzlich zu bekannten Charakter-Fakten
skill(talent,NAME,LVL) :- talent(NAME,LVL).
skill(combat_technique,NAME,LVL) :- combat_technique(NAME,LVL).
%% Option B: Charakter-Fakten ersetzen
skill(talent,NAME,LVL) :- __talent_wrapper((NAME,LVL)).
skill(combat_technique,NAME,LVL) :- __combat_technique_wrapper((NAME,LVL)).
%% Einzehlne Regel über eine Merkmalsgruppe
missing_min_lvl(FEATURE,NAME,LVL,MIN) :- skill(FEATURE,NAME,LVL), MIN = 0, LVL < MIN.
        \end{minted}
    \end{listing}
